LGWM

Right Screen, Wrong TransitionWorld Models as Verifiers for GUI Agents

LGWM is a latent world model that checks every step a GUI agent takes. It predicts the next screen in representation space and compares it with what actually appears, with no judge model and no attack labels.

Why verify transitions

A monitor that inspects only screens can be defeated by reusing a legitimate one. Judging a transition requires an expectation of what should have followed the action. Existing GUI world models provide one, but they output it as text, code or images, so checking it against the observed screen requires a second model to judge the two.

LGWM predicts in the space in which observations are encoded. It is a decoder-free, action-conditioned world model trained without semantic annotation on 1.85M real GUI transitions. Verification reduces to a vector comparison, and the same signal reveals whether a mismatch is harmful. World models have mostly served as simulators or planners; LGWM gives them a third role, verification.

How LGWM works

A ViT encoder turns the current screenshot into 512 visual tokens. An action encoder embeds the action type, its text and its touch coordinates. A Transformer predictor combines both and forecasts the tokens of the next screen. There is no image decoder and no autoregressive generation.

Training-free

Transition integrity

The cosine distance between the predicted and the observed next screen. It needs no attack labels, no benchmark supervision and no judge model.

Linear head

Harm score

An unexpected transition can still be harmless. A linear classifier on the prediction residual separates harmful violations from benign surprises.

Training starts from DINOv2, adapts the encoder to GUI screenshots, then trains the world model for 120,000 updates on transitions from Android in the Wild, AndroidControl, GUIOdyssey, AMEX and MiniWoB++. The inference model has 173M parameters.

Results on RSWT-Bench

RSWT-Bench contains 966 test transitions built around 222 donor pairs. Each credential screen appears under both a legitimate and a hijacked transition, so a detector that sees only the outcome screen scores 0.5 AUC by construction. Every method receives the same before screen, action and after screen.

RSWT: hijacked vs. legitimate credential transitions. Swap and Cred: benign mismatches vs. paired-safe and legitimate credential transitions. LGWM has 261M parameters in training and 173M at inference.

LGWM orders 219 of 222 donor pairs correctly. One decision takes 17 ms and 1.09 GB of memory: 64× faster and 16× lighter than Qwen3-VL-8B, and up to 7,000× faster than generative GUI world models, which also need a separate VLM judge.

The harm head reaches 0.954 AUC at separating harmful from benign violations, a task on which prompted VLMs are near chance.

Quick start

Score one transition from a before screenshot, an action and an after screenshot.

git clone https://github.com/jiamingzhang94/lgwm && cd lgwm
pip install -c requirements-tested.txt -e '.[text]'
hf download jiamingzz/lgwm --local-dir weights

echo '{"action_type": "tap", "x": 0.5, "y": 0.5}' > action.json
python tools/score_transition.py --before before.png --after after.png \
  --action action.json --harm-head weights/lgwm-harm-head

The command prints integrity and harm_score. The repository also covers evaluation on RSWT-Bench and training from scratch.

Questions

What is LGWM?
A decoder-free, action-conditioned world model for GUI agents. Given the current screenshot and an action, it predicts the representation of the next screen and compares it with the screen that actually appears. One cosine distance tells whether the transition is the one the action should have produced.
What is interaction hijacking, and why do screen-only monitors miss it?
An agent's action leads to a screen that is legitimate in another context, such as a real login page shown after tapping View order. The screen contains nothing malicious, so a monitor that inspects only the result cannot tell the hijacked case from the legitimate one. The evidence is in the transition.
What is RSWT-Bench?
A diagnostic benchmark with 966 test transitions built around 222 donor pairs. Each credential screen appears under both a legitimate and a hijacked transition, so any detector that sees only the outcome screen scores 0.5 AUC by construction.
How does LGWM differ from generative GUI world models?
Generative world models render the predicted future as text, code or pixels, then need a second model to judge it against the observed screen. LGWM keeps the prediction in representation space, so verification is a single vector comparison that takes 17 ms, where rendering a future can take up to 124 seconds.
Does LGWM need attack labels?
No. The world model is trained self-supervised, and the integrity score needs no labels or judge model. Only the optional harm head, a linear classifier on the prediction residual, is supervised.
